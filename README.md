# 网盘管理（整合版）

**一个程序 = V1 的界面与网盘管理能力 + V2 的自研播放内核。**

* **界面 / 网盘管理 / AI** 来自 `../网盘管理`（下称 **V1**）：顶栏网盘导航 + 左侧功能栏 +
  10 套主题的 GUI、百度/夸克/光鸭三家网盘适配器与子进程桥、传输引擎与敏感词上传守卫、
  AI 播放顾问 / 字幕助手 / 本地模型 / 模型商店 / 语音识别 / 价格时段预算……
* **播放** 来自本仓库原来的 V2：`ctypes` 直连 `libav*` 的**自研播放内核**（不使用 VLC、
  不调 `ffmpeg` 命令行），画面由 Qt 控件自绘；外加**弹幕引擎**、**TMDB 刮削**、**海报墙**。

**当前版本 [2.1.0](https://github.com/xugulin/wangpan-manager-v2/releases/tag/v2.1.0)**
（Linux 绿色版 `wangpan-manager-2.1.0-Linux.zip`，约 455 MB，解压即用）。

> 核心主张没变：**画面是我们自己画的**。
> 所以"视频跑到别的窗口里播放""切页黑屏""退出崩在 VLC 线程上"这一类问题，
> 在结构上不可能发生 —— 这也正是把 V1 的 VLC 播放栈整体换掉的原因。

旧的"纯 V2"说明存档在 `docs/旧README_V2.md`；整合审计报告在 `docs/整合/`。

**依赖方向是单向的**：`v8_3.* → wangpan.*`（功能层用内核）。
`wangpan/` 永远不 import `v8_3`，所以内核可以脱离这套 GUI 单独跑、单独测
（`tests/test_独立性.py` 钉住这条）。

## 怎么跑

```bash
./启动.sh                             # 图形界面（点左侧「🎬 播放」挑片子）
./一键启动_网盘管理_V2.sh              # 一键启动（文件管理器里双击也行）
./一键启动_网盘管理_V2.sh --check       # 只自检：解释器 / PySide6 / 界面层依赖 / libav* / 三家网盘目录
./启动.sh --纯播放                     # 只起 V2 的纯内核窗口（排查播放问题用）
./启动.sh --cli 网盘列表               # 命令行模式（同 V1 的 --cli）
./启动.sh --调试 / --静默 / --日志级别 警告 / --跳过自检
运行环境/venv/bin/python -m unittest discover -s tests -t .
运行环境/venv/bin/python 工具/整合验收.py     # 离屏抓图 + 真播一段（见下）
```

**快捷键**（整合后补的，键鼠切换不用去够左侧按钮）：

| 按键 | 作用 |
|---|---|
| `Ctrl+1`…`Ctrl+8` | 网盘 / 传输 / 播放 / 媒体库 / 敏感词 / AI / 日志 / 设置 |
| `Ctrl+Shift+P` | 显示 / 隐藏右侧「播放清单 + AI 助手」面板（就是顶栏那个「🗂 面板」） |
| `Ctrl+Q` | 退出（走完整收尾：停线程 / 存位置 / 关库 / 停 AI 子进程） |
| `空格` / `←` `→` / `.` / `[` `]` / `PgUp` `PgDn` / `F` / `Esc` | 播放暂停 / 跳转 / 逐帧 / 调速 / 上下集 / 全屏 |

窗口标题跟随当前页与正在播的片名（`网盘管理 · 🎞 媒体库 · ▶ 沙丘.mkv`），
任务栏一眼能看出停在哪一页。

* **桌面图标 / 应用菜单**：`工具/安装快捷方式.sh`（Linux）、
  `工具/安装快捷方式.ps1`（Windows，`powershell -ExecutionPolicy Bypass -File …`）。
  只想在**工作区**里生成一个 `.desktop`（不动菜单与桌面、方便先看一眼或自己拷走）：

  ```bash
  工具/安装快捷方式.sh --工作区      # → ./网盘管理.desktop（可执行、已过 desktop-file-validate）
  ```

  产物里带的是**本机绝对路径**（`.desktop` 的 `Exec`/`Path`/`Icon` 只能写绝对路径），
  所以它和 `配置.json` 一样属于生成物、已在 `.gitignore` 里；换台机器重新生成即可。
  `%F` 也接好了：把视频拖到图标上就直接开播。
* **依赖**：`requirements.txt`（清单是按**源码 AST 扫描**列的，不是照抄旧环境）。
  自带 venv 里已经装好；换机器时
  `运行环境/venv/bin/pip install -r requirements.txt`。
* **libav\***：Linux 装系统 `ffmpeg` 包；Windows 把 `avformat-*.dll` 等放进 `运行环境/libav/`。
  播放本身**不需要 `ffmpeg` 命令行**（只有"造测试素材"和"读媒体元数据给 AI 用"才用）。

## 整合做了什么

### 1. 播放：VLC 那一套整体换掉

删掉的模块（它们存在的唯一理由就是"把画布交给外部播放器"）：

| 删掉 | 原来干什么 |
|---|---|
| `播放/vlc绑定.py`（1235 行） | ctypes 驱动 libvlc |
| `播放/播放核心.py`（1288 行） | 播放会话：取直链→探测→起播→统计 |
| `播放/播放出口.py` | `set_xwindow` 交句柄 + "停干净/等 vout 消失/再绑定"的交接仪式 |
| `播放/显示环境.py`、`播放/游离窗口.py` | 平台判定、X11/Win32 窗口巡检纠正"画面游离" |
| `界面/窗口就绪.py`、`界面/游离窗口守护.py` | 窗口映射判定与自愈巡检 |
| `界面/播放控件.py` | 给 libvlc 嵌的原生窗口控件 |

**新增**（在 V2 侧，纯内核、不依赖界面层）：

* `wangpan/ui/播放会话.py` —— 把 V2 引擎包装成界面认的那套"会话"接口：

  * 方法：`准备 / 起播 / 暂停 / 跳转 / 设置音量 / 设置速率 / 挂字幕 / 切换字幕 / 截图 /
    状态快照 / 流畅优先 / 规则诊断 / 采样并诊断 / 应用新参数 / 安全回退画面 / 关闭 /
    装主线程泵 / 排空主线程队列 / 取适配器`
  * 属性：`播放器 / 设置 / 媒体 / 探测 / 直链信息 / 网盘标识 / 远端路径 / 标题 / 自动调优 /
    AI决策状态`
  * `状态快照()` 的 **21 个键**与 **8 个中文状态串**（`空闲/打开中/缓冲中/播放中/已暂停/
    已停止/已结束/出错`）按老契约原样复刻 —— AI 顾问与界面都按它判断（有测试钉住）。

* `wangpan/ui/播放页.py` —— 内核级播放页：画面 + 控制条 + **弹幕** + 字幕 + 进度缩略图。
* `v8_3/界面/播放页面.py`（重写）—— V1 的对外契约 + V2 的内核：
  保留网盘/路径浏览行、`ℹ️视频信息 / 📋播放清单 / 🤖AI助手` 三个面板、
  VLC 风格的菜单动作表、独立窗口、全屏、截图提示。

**顺手做掉的整合优化**：

1. **不再有窗口句柄**：`起播(句柄)` 的句柄参数保留但忽略；`绑定窗口` 变成空实现。
   少掉"先停干净 → 等 vout → 再绑定"整套仪式与它的失败模式。
2. **主线程泵变成直通**：V2 引擎自身线程安全，后台线程直接调控制方法即可
   （老内核必须"非界面线程全部排队"，否则在 `libvlc_media_add_option` 里 SEGV）。
3. **独立窗口不再复制播放器**：把**同一个播放页 `setParent()` 搬过去**，
   于是同一个会话、同一个弹幕控制器、同一份取帧循环；关掉再搬回来。
4. **AI 参数语义重映射**：老内核的 `网络缓存毫秒` 是 libvlc 私有选项，
   现在换算成 **libavformat 的读缓冲字节数**（按码率折算，夹在 256KB–32MB）；
   `硬解` 映射成"这一路允不允许硬解"（`解码.py` 新增 `允许硬解` 开关）；
   `附加选项` 保留字段但不生效（libav 没有这个概念）。
5. **命令行/文件管理器直接开播**：`启动.sh 某视频.mp4`（或"用本程序打开"）——
   多选时第一个开播、其余按顺序进播放清单。这条以前接了参数却没人用（实际被丢掉）。
6. **给 AI 补上它一直缺的"缓冲中"信号**：V2 内核没有这个状态，但 AI 顾问明确要求
   "正在缓冲时不许把缓存改小"。现在用**播放时钟是否推进**推断出来，
   于是顾问的自动调优第一次有了真实触发条件。

### 2. 界面：V1 的主窗口当合并后的主窗口，多了一页「媒体库」

V1 的 6 个业务页（网盘 / 传输 / 敏感词 / AI / 日志 / 设置）都是按
`(主窗口, 父=None)` + `主窗口.动作/配置/AI运行时` 这套契约写的，所以直接沿用；
V2 的**海报墙 / 详情页 / 待确认队列 / 手动匹配 / 手动资料 / 弹幕设置**被包成
`wangpan/ui/媒体库页.py`（自包含：自己持有资料库与图片缓存、自己起刮削线程、
对外只发信号），作为左侧功能栏的第 3 项「🎞 媒体库」接进来。

### 3. AI：全部功能保留，并按新内核适配

| 功能 | 状态 |
|---|---|
| AI 页（状态 / 设置 / 模型商店 三页签，预算、价格表、运行详情） | ✅ 原样（截图见下） |
| AI 智能助手（9 家 OpenAI 兼容厂家 + 本地 ollama + 规则三级降级） | ✅ 原样 |
| AI 传输调度（队列特征 → 并发/优先级/重试策略，带缓存/限频/学习库） | ✅ 原样（挂在传输页） |
| 字幕助手（翻译字幕 / 总结章节标签）+ AI 播放面板 | ✅ 原样 |
| 播放顾问（起播参数 + 卡顿诊断 + 效果学习库） | ✅ 适配新内核（见上"语义重映射"） |
| 本地模型（内置 ollama 基座、模型市场、一键装） | ✅ 原样 |
| 语音识别（faster-whisper 独立环境 → SRT） | ✅ 原样（本机缺模型，会如实提示安装步骤） |
| 价格抓取 / 时段预算 / AI 学习库 | ✅ 原样 |

**同时补掉了审计查出来的三个收尾缺口**（原来是真缺口，不是猜测）：

* `ollama serve` 被 `start_new_session=True` 拉起后**全项目没有任何地方停它** →
  新增 `本地模型客户端.停止服务()`，退出时收；
* Whisper 工作进程（模型常驻几百 MB）的 `卸载()` **全文没有调用点** →
  关播放页与退出时收；
* `AI运行时.关闭()` 原来只关学习库 → 现在把上面两样一起收。

### 4. 顺手修的既有缺陷

| 缺陷 | 位置 | 修法 |
|---|---|---|

### 5. 用户真机使用后反馈的问题（已修）

用户在这台电脑上真用了一遍，报了三件事，各自都是真 bug：

| 现象 | 根因 | 修法 |
|---|---|---|
| 播放时点「🗂 面板」，窗口宽高跟着变 | `切换侧栏` 顺手调了 `重排`，而 `重排` = `按视频比例调整窗口`，里面直接 `窗口.resize(...)` | `切换侧栏` 只显示/隐藏侧栏；画面尺寸改由 `视频控件.尺寸变了` 通知引擎（**永不改窗口**） |
| 多点两次面板，窗口崩溃 | 窗口一 resize 就调 `解码.设置输出尺寸`，而原实现在**界面线程**里 `sws_freeContext` + 清零 `_目标宽/_目标高`，解码线程正在 `取帧` 里用它们 → use-after-free / 按旧尺寸越界写 | 界面只**登记请求**（单个元组赋值，原子），解码线程在 `_准备缩放` 的安全点自己应用 |
| 窗口一变，画面左上角没跟播放器左上角对齐 | 画面原本**居中**摆放，窗口一变宽窄就左右"跳" | 画面改成**贴左上角**（多余的地方在右/下留黑边），窗口怎么拖画面都不动 |

崩溃的复现与验证都留在测试里：

```
复现（改前 3/3 必崩）：播放中每 2ms 改一次随机输出尺寸 → 进程 core dump
改后：同一脚本 3 次各改约 3500 次尺寸，帧序号照常增长（3/3 存活）
离屏用例：tests/test_体验.py::播放中改输出尺寸测试（崩了就是测试进程死掉，CI 必红）
真机用例：工具/真机测试.py [2.5] 播放中反复改窗口尺寸（xdotool windowsize，连改 6 次）
契约用例：tests/test_解封装解码.py::输出尺寸线程安全测试（登记请求不许当场改解码状态）
摆放用例：tests/test_字幕.py::画面摆放测试（目标矩形恒为 (0,0,w,h)）
```

顺带把真机测试的两处**误报**也修了（它们会把"环境读不到"说成"软件坏了"）：

* 翻页断言原来看**窗口标题**：XWayland 下实测会读到过期标题（应用日志已经
  "切到 媒体库"、`xdotool` 读到的还是上一页），一次报了 8 项没通过。现在
  **标题或应用日志任一证实即可** —— 应用自己写的 `[界面] 切到 X` 才是权威信号。
* 面板开关原来打算点像素坐标 / 按快捷键触发，两者都受焦点与坐标影响；
  现在用 `xdotool windowsize` 直接改窗口尺寸（等价于用户拖窗口/点面板），不依赖焦点。

**真机才暴露的三件事**（都写进 `工具/真机测试.py` 的注释了）：

1. `xdotool windowclose` 在 XWayland 下**不投递** `WM_DELETE_WINDOW` ——
   应用当然不退出，看上去像"关窗有 bug"。现在自己按 X11 协议发那条 ClientMessage。
   （写这个助手时我自己还先踩了一次"ctypes 不声明 argtypes → 指针截断 → 段错误"，
   正是本项目文档里警告过的那个坑。）
2. 系统对话框（COSMIC 的「允许远程控制?」）随时可能抢焦点，键盘就进不到应用里 ——
   所以断言不能只看截图，要读**窗口标题**（不依赖焦点）。窗口标题跟随当前页，
   就是为此加的。
3. 全屏往返之后合成器会把窗口重新摆放（实测 (580,236) → (196,284)），
   按启动时缓存的几何算出来的点击坐标就全空了 ⇒ 每次点击前重读几何，
   并**边点边看标题自标定**按钮位置（字体/主题/分辨率变了也不用改代码）。

原生 Wayland 下的限制（如实写出来，不假装通过）：外部工具**没有**"激活某个窗口"的协议，
`wtype`/`ydotool` 的键只会发给当前焦点窗口；焦点在别处时键全丢。所以
`--平台 wayland` 在无焦点时会明确报「跳过」并给出做法（先用鼠标点一下窗口再重跑），
而**完整的交互覆盖由 `--平台 xcb` 提供** —— 同一份二进制、同一批代码路径，
只是 Qt 平台插件不同；Wayland 下的渲染与播放由 `grim` 截图证明。

### Windows 路径怎么在本机验（wine）

GitHub 的 Windows runner 一次要排队 + 跑十分钟，所以本机用 **wine 11** 先把 Windows
那条路验一遍（wine 提供的是真的 PE 加载器 + 真的 `python314.dll`）。

```bash

#   2) Windows 版 libav DLL —— **必须 avcodec 63**（偏移表是按 63 生成的，

7z x -y -o构建/windows/ffx /tmp/ff-win.zip
```

三个脚本里写的都是**踩过的坑**，值得留意：

* **`-snl` 必须有**（打包）：不加它 7z 会把符号链接**解引用成文件本体** ——
  `venv/bin/python3` 被存成 32MB 的 python 副本（解压后报 `No module named 'encodings'`），
  `venv/lib64 -> lib` 被整份复制（+756MB）。实测 974MB/解压即坏 → 加了三处都对、455MB。
* **启动器自愈**（`启动.sh` / `一键启动_网盘管理_V2.sh`）：`7z x` 出于安全会**拒绝创建**
  "指向目录之外"的符号链接（实测丢 302 个，其中包括 venv 的解释器链接）。
  启动脚本在起 python 之前按实际位置把链接和 `pyvenv.cfg` 的 `home` 补回来（幂等），
  于是用户用 7z / unzip / 文件管理器解压都能用。开发树里本来就好的环境**不会被改**。
* **只在包内跑一遍测试不算数**：包里是"重建过的 venv + 相对链接 + 占位路径"，
  和源码树是两套东西。`构建/验证发布包.py` 会把包解压到 `/tmp/验证发布包/` 再验 ——
  实测就是靠它抓到"漏了 `资源/`（图标素材）3 条测试红""符号链接被解引用""venv 起不来"。

## 已知限制 / 下一步

* **多音轨切换**：V2 内核目前只播第一条音轨（菜单里如实返回"没有这个能力"，
  不假装成功）。内嵌多音轨/多字幕轨的切换在路线图里。
* **缩放 / 宽高比**：画面永远保持源比例摆放（这是不变形的唯一正解），
  菜单里的缩放/宽高比只记账、不改变形。
* **`数据/` 里两套配置并存**：V1 的 `配置.json`（适配器/传输/AI/敏感词）是主配置；
  V2 的 `数据/网盘.json`（本地/HTTP 适配器）只服务 `--纯播放` 那条路。
  整合界面里的网盘列表来自 V1 的适配器注册表。
* **媒体元数据**用 ffprobe 读（给 AI 顾问用）；播放内核本身完全不碰外部命令。
* **真机自动化在原生 Wayland 下只能验到"启动/渲染/播放"**：Wayland 不给外部工具
  "激活窗口"的协议，键盘注入只对焦点窗口有效。完整交互（翻页/点击/全屏/关窗）
  在 `--平台 xcb`（XWayland）下是全自动且全覆盖的。
* **本机没装 Whisper 模型**（461 MB），所以「AI 生成字幕」会提示安装步骤而不是直接可用；
  语音识别环境（`运行环境/语音识别/venv`）已经就位。
* **一键更新（设置页）已停用**：上游仓库发布的还是**旧版（VLC 内核）**的包，
  点「下载并更新」会把整合后的程序覆盖回旧形态。现在只保留"看版本 / 打开发布页"，
  更新动作会明确说明原因并拒绝。想升级请用 `git pull`；等整合版发布自己的 Release 后，
  把 `v8_3/更新.py` 里的 `仓库` 指过去并把 `更新源已就绪` 置 `True` 即可。
* **V1 的 `构建/` 没有搬过来**（它是围绕 VLC 发布包写的：内置 VLC 运行时、校验插件数量），
  整合后不适用。取而代之的是本仓库自己的三个脚本（见下「打包与发布」）。
  装依赖用 `requirements.txt`，快捷方式用 `工具/安装快捷方式.*`。
