# 架构与路线图（整合版）

> 这个仓库现在是**合并后的项目**：V1 的界面/网盘管理/AI + V2 的自研播放内核。
> 完整背景与迁移清单见 `docs/整合/`（00 整合方案 + 5 份只读审计报告）。

## 一、分层（每层都能单独测）

```
启动.py
  └─ v8_3/界面/主窗口.py              ← V1 的 GUI（顶栏网盘导航 + 左栏 + QStackedWidget）
        ├─ 网盘页面 / 传输页面 / 敏感词页 / AI页面 / 日志页 / 设置页   ← V1 的功能页
        ├─ wangpan/ui/媒体库页.py      ← 海报墙 + 详情页 + 刮削 + 待确认
        └─ v8_3/界面/播放页面.py        ← 播放页：V1 的对外契约
              └─ wangpan/ui/播放页.py   ← 画面 + 控制条 + 弹幕 + 字幕 + 预览
                    └─ wangpan/ui/播放会话.py   ← V2 引擎 → 界面/AI 认的那套接口
                          └─ wangpan/player/引擎.py
                                ├─ 解封装.py   ← 容器 → 包（时间统一成"秒"）
                                ├─ 解码.py     ← 包 → RGB 帧 / S16 音频块（VAAPI/D3D11VA 硬解）
                                └─ 音频输出.py ← PulseAudio / 空设备
                                      └─ wangpan/ffmpeg/绑定.py（+ 偏移.py）← 只认整数地址
```

**另一条路（回归用）**：`启动.py --纯播放` → `wangpan/ui/主窗口.py`
（只加载 V2 内核 + 网盘页 + 媒体库页，**完全不碰 v8_3**）。

**V1 侧还有三条独立链路**（与播放无关）：

```
网盘操作：v8_3/核心/适配器.py → 子进程客户端 → 桥/工作进程.py（行式 JSON-RPC）
                                                   → 适配器/<某网盘>/核心（各自独立的小项目）
传输/敏感词：v8_3/核心/传输引擎.py（线程池 + 可调许可 + 退避 + SQLite 任务库）
              └─ 上传那一步被 敏感词/上传守卫.py 接管（AC 自动机 + 预检改名 + 学习闭环）
AI：v8_3/AI/运行时.py（门面）
     ├─ 智能助手（9 家 OpenAI 兼容网关 + 本地 ollama + 规则，三级降级）
     ├─ 调度器（队列特征 → 并发/优先级/重试；缓存 + 限频 + 学习库）
     ├─ 字幕助手 / 播放顾问（笔记 + sqlite 学习库）
     └─ 本地模型 / 模型市场 / 价格抓取 / 时段预算
```

## 二、播放内核：三个线程与背压（V2 原有设计，未变）

| 线程 | 干什么 | 队列 |
|---|---|---|
| 解封装 | `av_read_frame` → **复制包**（引用共享）→ 分派 | 视频 96 包 / 音频 192 包（满则等，超时丢包） |
| 视频 | 送包 → 收帧 → swscale 成 RGB0 → 按音频时钟等待/丢帧 → 交"最新帧" | 只保留最新一张（界面按需取） |
| 音频 | 送包 → 收帧 → swresample 成 S16/48k/立体声 → 写设备 → **推进时钟** | — |

* **音频是主时钟**：`已写样本 / 采样率 − 设备延迟`；
* 视频提前量 4ms、丢帧阈值 80ms（可调）；
* 暂停 = 三个线程都在等待，不忙等；跳转 = 冲刷队列 + `avcodec_flush_buffers` +
  `avformat_seek_file` + 时钟复位。

**画面由 `wangpan/ui/视频控件.py` 用 QPainter 画**（帧 → QImage → 控件，
字幕与弹幕在**同一次 paintEvent** 里叠加）。因此：

* "视频跑到别的窗口里播放"结构上不可能发生；
* 两个页面（主界面 + 独立窗口）可以显示同一路播放，各自取帧 ——
  独立窗口甚至是把**同一个播放页 `setParent()` 搬过去**，连弹幕状态都不用同步。

## 三、踩过的坑（写在代码注释里，别再犯）

1. **跨线程共用 `AVPacket`**：解封装线程马上会往同一个包里读下一个包 → 解码线程拿到被覆盖的
   数据（实测 `Invalid NAL unit size` 之后段错误）。⇒ 必须 `av_packet_ref` 复制引用。
2. **队列条目类型不统一**（一处放字典、一处放元组）→ 消费端解包炸。
   ⇒ 统一 `("包", 指针)` / `"冲刷"`。
3. **手写 ctypes 结构体会随 FFmpeg 大版本错位**，错位读出来"看着像数字"，极难查。
   ⇒ 用 C 编译器的 `offsetof` 生成 `偏移.py`，并在启动时做 ABI 自检。
4. **`int(c_void_p)`** 会去解析它包装的字节串（`ValueError`）—— 绑定层统一用整数地址。
5. **（整合新增）控制条能把页面的最小宽度顶到 1400px**，放进 `QSplitter` 后
   右侧面板被挤出窗口（离屏抓图才看出来）。⇒ 按钮行必须包在横向滚动区里。
6. **（整合新增）`QThread` 被销毁时还在跑 → Qt 直接 abort，`try/except` 抓不住。**
   所以退出收尾要覆盖：播放页定时器、独立窗口、AI 常驻子进程（ollama / Whisper）、
   刮削线程、适配器子进程。

## 五、验收判据

* **画面必须在自己的窗口里**：V2 天然成立，并且是**结构性**的 ——
  `tests/test_可移植性.py` 钉住"播放路径上不许再出现 `set_xwindow`/`set_hwnd`/`libvlc_`"
  与"游离窗口巡检模块必须已删除"；
* **不依赖外部命令**：`tests/test_独立性.py` 扫播放路径禁止 `ffmpeg`/`ffprobe`/`vlc` 命令行；
* **内核独立**：`wangpan/`（尤其 `player|ffmpeg|subtitle|danmaku|scrape|pan|transfer`）
  不许 import `v8_3`；`wangpan/ui/主窗口.py` 同样不许（`--纯播放` 那条路必须真独立）；
  内核只许标准库 + PySide6，第三方依赖只出现在 `v8_3/` 那一层；
* **AI 契约不许破**：`状态快照()` 的 21 个键、8 个中文状态串、播放器门面的方法名，
  都有测试钉住（`tests/test_整合.py`）；
* **退出必须干净**：关窗收尾要覆盖播放定时器、独立窗口、AI 常驻子进程、刮削线程、适配器桥。
