# V2 架构与路线图

## 一、分层（每层都能单独测）

```
启动.py
  └─ wangpan/ui/主窗口.py ── 视频控件.py     ← 画面由我们自己画
        └─ wangpan/player/引擎.py            ← 播放器循环（三个线程 + 音频主时钟）
              ├─ 解封装.py                    ← 容器 → 包（时间统一成"秒"）
              ├─ 解码.py                      ← 包 → RGB 帧 / S16 音频块
              └─ 音频输出.py                  ← PulseAudio / 空设备
                    └─ wangpan/ffmpeg/绑定.py（+ 偏移.py）  ← 只认整数地址，字段按偏移读
```

## 二、三个线程与背压

| 线程 | 干什么 | 队列 |
|---|---|---|
| 解封装 | `av_read_frame` → **复制包**（引用共享）→ 分派 | 视频 96 包 / 音频 192 包（满则等，超时丢包） |
| 视频 | 送包 → 收帧 → swscale 成 RGB0 → 按音频时钟等待/丢帧 → 交"最新帧" | 只保留最新一张（界面按需取） |
| 音频 | 送包 → 收帧 → swresample 成 S16/48k/立体声 → 写设备 → **推进时钟** | — |

* **音频是主时钟**：`已写样本 / 采样率 − 设备延迟`；
* 视频提前量 4ms、丢帧阈值 80ms（可调）；
* 暂停 = 三个线程都在等待，不忙等；跳转 = 冲刷队列 + `avcodec_flush_buffers` +
  `avformat_seek_file` + 时钟复位。

## 三、踩过的坑（写在代码注释里，别再犯）

1. **跨线程共用 `AVPacket`**：解封装线程马上会往同一个包里读下一个包 → 解码线程拿到被覆盖的
   数据（实测 `Invalid NAL unit size` 之后段错误）。⇒ 必须 `av_packet_ref` 复制引用，
   消费端 `av_packet_free`。
2. **队列条目类型不统一**（一处放字典、一处放元组）→ 消费端解包炸。
   ⇒ 统一 `("包", 指针)` / `"冲刷"`。
3. **手写 ctypes 结构体会随 FFmpeg 大版本错位**，错位读出来"看着像数字"，极难查。
   ⇒ 用 C 编译器的 `offsetof` 生成 `偏移.py`，并在启动时做 ABI 自检。
4. **`int(c_void_p)`** 会去解析它包装的字节串（`ValueError`）—— 绑定层统一用整数地址。

## 四、里程碑

| 里程碑 | 内容 | 状态 |
|---|---|---|
| **M1 自研内核** | 解封装/解码/缩放/重采样 + 音频主时钟 + 自绘控件 + 播放/暂停/跳转/音量/截图/统计 | ✅ 已完成（真机验证） |
| M2 硬解 | VAAPI（Linux）/ D3D11VA（Windows）解码 → 零拷贝上屏（GL/D3D 纹理）；失败自动回退软解 | ⏳ |
| M3 网络播放 | 自研 HTTP(S) 数据源：Range 请求、自定义头（UA/Referer/Cookie）、重连、缓冲水位；接网盘直链 | ⏳ |
| M4 字幕 | SRT/ASS 解析 + 自绘叠加（含字体/描边/位置）；字幕轨选择 | ⏳ |
| M5 播放器体验 | 倍速（音频重采样补偿）、逐帧步进、缩略图/进度预览、章节、记忆播放位置 | ⏳ |
| M6 网盘功能 | 网盘适配器（V2 自己的实现，独立于 V1）、传输引擎、AI 相关能力 | ⏳ |

## 五、验收判据（沿用 V1 的教训）

* **画面必须在自己的窗口里**：V2 天然成立，但要有测试钉住（`tests/test_引擎.py` +
  真机截图）；
* **4K60 能播**：软解（多线程）+ 硬解都要过，丢帧率与 CPU 占用要记录；
* **不依赖外部命令**：`tests/test_独立性.py` 扫源码禁止调 ffmpeg/ffprobe/vlc 命令行；
* **完全独立**：禁止引用 V1 的路径/包名。
