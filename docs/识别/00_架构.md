# 媒体识别改造：从零架构

> 目标一句话：**把"猜"变成"可度量的识别"**——任何"我觉得更准了"都必须拿标注集的指标说话。

## 一、为什么推倒重做

现在的识别等于"一个 `解析()` 函数 + 一次 TMDB 搜索 + 一个分数阈值"。真机上暴露出来的问题：

| 现象 | 现状 |
|---|---|
| `146.SDR.8bit.2160p.60fps.DDP5.1.WEB-DL.H265.mp4`（网盘为规避限制改的名字） | 标题 = `146 SDR 60fps DDP5 1`，**季/集都丢了** |
| `Renegade.Immortal.S01E138.2023.…mkv` | 识别正确（只认这一种写法） |
| 中文剧集用英文名搜 | 靠模糊搜索碰运气 |
| 改了规则到底是变好还是变坏 | **无法回答**（没有评测集） |

四条根因：① 只支持一种命名风格；② 标题被画质标签污染；③ 只搜一次、只有一个查询词、只有一个分数；④ **没有尺子**。

## 二、验收指标（先定尺子，再动手）

在自建标注集（`数据/识别标注.jsonl`，全部来自**真机真实遇到的文件名**）上：

| 层 | 指标 | 门槛 |
|---|---|---|
| 结构抽取（类型/季/集/年份） | 准确率 | **≥ 99%**（纯规则问题，必须接近满分） |
| 标题清洗（不含画质标签） | 准确率 | ≥ 98% |
| 作品识别（TMDB Top-1） | 准确率 | ≥ 95% |
| **自动入库** | 精确率 | **≥ 99%**（宁可进"待确认"，也绝不把错的写进库） |
| 别名命中（中文名 ↔ 英/日别名） | 命中率 | ≥ 90% |

`工具/识别评测.py` 每次跑出上表 + **失败样例清单**；指标只许升不许降，降了就是回归。

## 三、分层（每层独立可测，层间只传数据结构）

```
文件/目录名
   │
   ▼ ① 归一化   全角→半角、统一分隔符、去掉广告尾巴（网址/QQ群/公众号/压制组）、去扩展名
   ▼ ② 结构抽取  文件名 + 目录名 + 同目录兄弟文件 → {标题候选, 年份, 季, 集, 集到, 版本, 是否打包}
   ▼ ③ 候选生成  排序过的**多个**查询词：文件标题 / 目录标题 / 别名库 / 去标签后最长中文段
   ▼ ④ 检索      多查询 × (电影+剧集) 接口，合并去重；同目录只搜一次（缓存）
   ▼ ⑤ 打分消歧  多信号可解释打分（见下）+ 用户确认学习库
   ▼ ⑥ 决策      三档：自动入库 / 待确认 / 丢弃（自动档要求"高分 **且** 领先第二名足够多"）
   ▼ ⑦ 落库学习  落库；**每次人工确认都写成学习样本**（别名映射、目录→作品映射），下次直接命中
```

### ② 结构抽取要覆盖的写法（真机+常见）

- 集号在前：`146.SDR.8bit.2160p…`、`05.mkv`、`12 - 标题.mp4`
- 标准：`S01E138`、`s1e3`、`1x03`
- 中文：`第03集`、`第3话`、`03话`、`第三集`
- 字幕组：`[组名] 标题 - 03 [1080p][中字]`
- 特殊：`SP`、`OVA`、`特别篇`、`NCOP/NCED`、`合集`、`完结`、`更新至12`
- 多集打包：`E01-E12`、`01-12`
- **年份防误判**：`2012.mp4`、`1917.2019.1080p.mkv` 不许当集号
- **上下文信号**（爆米花识别准的关键）：同目录 N 个文件、编号是否连续 → 判定"这是剧集目录"还是"散装电影"

### ⑤ 打分信号（线性、可解释、可调）

| 信号 | 说明 |
|---|---|
| 标题相似度 | 中/英分开算（中文用字符重合+编辑距离，英文用词重合） |
| 年份接近度 | 完全一致最高；差 1 年次之；差 ≥3 年重罚 |
| 类型/上下文一致 | 剧集目录命中 tv、单片命中 movie；**不一致重罚** |
| 季集范围 | 抽到的 (季,集) 要落在候选的季数与集数范围内 |
| 热度/票数 | 弱先验，只用于同分打破 |
| 学习库 | 同一目录/同一别名历史确认过 → 强加权（这是"越用越准"的来源） |
| margin | 第一名 − 第二名的差值；差值小 → 一律进"待确认" |

## 六、几条硬规矩

1. **标注集是唯一权威**：没有它不许说"更准了"。
2. **自动化要保守**：自动入库要求高分 + margin；拿不准一律"待确认"（用户点一下，同时变成学习样本）。
3. **不许为了对个案而写死**：规则必须能解释、能泛化；个案进标注集，不进 `if`。
4. **每次改动跑评测**：指标降了就是回归，不允许合入。
5. **真机复验**：这套东西最终要在**这台电脑上、用真实网盘目录**跑通才算完成（用户明确要求）。

## 七、P5 接线时的取舍与遗留（**如实记录**）

### 1) `命名解析.解析()` 怎么变成薄壳的

新老两个解析器**共存的代价**是"两套真相"，所以 P5 做的事是"结构只有一处实现"：

* **结构字段**（标题/年份/类型/季/集/集到/特别篇）→ 转调 `identify.结构.抽取`
  （P1 那一层，91/91）。老调用方（扫描器、服务层、界面、`猜剧集路径`）拿到的仍是
  原来那个 `解析结果` 对象，**字段名与类型一个没变**；
* **老字段继续由老规则补齐**（新结构层不产出这些，去掉就是既有功能悄悄退化）：
  `数据源`/`数据源ID`（`[imdbid-…]`）、`版本`（1080p/WEB-DL…）、`段`（cd1/part1）、
  `三维`（FTAB/HSBS）、`标记`（default/forced/语言码）、`是番外`（-trailer/花絮目录）；
* **日期式命名**（`Show Name 2021-05-01 Title.mkv`，Plex 惯例：季=年份、集=MMDD）
  架构第二节的写法清单里没有它、新结构层也没实现 —— 这是"新层不产出"的**写法级**缺口，
  薄壳里按老规则补（`命名解析.解析` 里那段 `if 日期`）；
* **两处口径差异（都在薄壳里按老口径补，且都有意为之）**：
  1. `2012.mp4`：P1 的口径是"摘掉年份后标题不能为空"→ 年份 `null`、标题 `2012`；
     老契约要 `年份=2012`（`年份防误判测试` 钉着）。薄壳按老口径补年份，
     **服务层走 `结构.抽取`，不受影响**；
  2. 片名里本来就有 `3D`（`Awesome 3D Movie (2022).3D.FTAB.mp4`）：新结构层把 `3d`
     当发布标签一并摘掉 → 标题成了 `Awesome Movie`；老规则是"先摘 3D 格式标记、再算标题"。
     薄壳只对"确实带 3D 标记"的文件把标题按老规则补回来。

### 2) 为了让老契约继续绿，结构层（P1）被补了 5 处规则

这些不是"为个案写死"，是**老实现本来就有、新实现漏了**的真实能力（每一处都有回归测试
或真机样本盯着）；补完 `工具/识别评测.py --实现 新` 复跑仍是 **91/91＝100%**：

| # | 缺口 | 症状（真机/老测试） | 补法 |
|---|---|---|---|
| 1 | `剧名 第2季` 形态的目录 | `仙逆 第2季/146.mp4` 被判成第 1 季 → 文件挂到错的季 | `结构._扫目录季` 加第二遍扫"名字里夹着的季标识"（整名是季目录的优先级不变） |
| 2 | `[tmdbid-123]` 里的数字 | `Movie (2021) [tmdbid=123].mkv` 被当成第 123 集 | 数据源 ID 标签整块进"排除段"（与发布标签/年份同级） |
| 3 | 末尾**光秃秃**的裸数字 | `13 Going on 30.mkv`（30）、`Movie 3.mkv`（3）被当成集号 | 末尾裸数字要求"有前导零 / 在括号里 / 有季目录上下文 / 前面没有实词"（老实现坑 2 的规则） |
| 4 | 更新状态污染目录名标题 | 目录 `某剧 更新至146集` → 标题成了整个目录名，搜 TMDB 一条都搜不到 | `归一化` 增加"更新状态"（`更新至N集`/`全N集`/`已完结`/`合集`）并进"去发布标签/标签段" |
| 5 | 兜底标题把季集标记当片名 | `S01E01 - 1080p.mkv` 的标题成了 `S01E01`（老实现坑 5） | 兜底前先把标记本身挖成等长空格 |

顺带补了一条**能力**：目录名**括号里的年份**也算年份（`怪奇物语 (2016)/Season 01/…` → 2016）。
为什么值得：年份是打分里最硬的独立证据，不认它，"最规范的目录写法"反而永远进不了自动档。
只认括号里的（裸数字目录 `2012`/`1917` 是分类或片名），所以不会误伤。

### 3) 决策层补回"精确一致唯一"（这是**规则回归**，不是放宽标准）

老实现 `匹配打分.自动决策` 有一条真机测真 API 之后加上的例外：**片名一模一样 + 年份对得上
→ 直接采纳**（否则队列会被 `沙丘 (2021)` 这种"一眼就能定"的条目淹掉，
`tests/test_tmdb真HTTP.py::端到端队列测试` 钉着它）。P3 的 margin 规则没有这一条，
接线时如果不补，这条既有行为就没了，所以补在了 `决策._精确一致`，并且**比老实现更严**：

* 只认**主标题**（`结构.标题`）与候选名字**逐字符一致**（只忽略大小写/空格/标点）——
  不拿"目录链"或"剥掉数字后的相似度"当证据（真机上正是它让"沙丘"与"沙丘 2021"互相判成
  一字不差，冒出一个假重复条目）；
* 且候选里**有且仅有它一条**满足、它必须就是首选；
* 硬条件（标题下限 / 类型 / 年份反证 / 季集越界）仍然**单项否决**，排在这条规则之前；
* 顺序放在"绝对分/间距"之前（老实现也是这个顺序）。

复跑证据（`数据/识别打分评测.md`）：**自动入库 49/49＝100%（一条不错）、Top-1 63/63＝100%**，
覆盖率 **68.3% → 77.8%**（多自动入库 6 条，全部正确）。
`tests/test_识别决策.py::分数低但标题像的_仍然待确认而不是丢弃` 也仍然绿 ——
"只有名字像、年份未知、分又不够"照样进待确认。

### 4) 服务层的两处结构性改动

1. **丢弃怎么落**：新链的三档要落到既有设施上。自动入库/待确认都沿用原路
   （补季集 → 挂文件 → 存条目 → 记任务；候选进"刮削任务"的 `候选` JSON 列，
   **数据结构没变**，`ui/待确认.py` 与 `媒体库页.开待确认队列` 不用改一行）。
   丢弃则**不进待确认队列**，但会把任务状态记成 `跳过`（与"忽略待确认"同一个状态）：
   * 为什么不直接删行：删了 `续跑` 会在下一批又把它从"待处理"里捞回来（任务表是
     "待处理/失败"才重试，`跳过` 不重试），而且"为什么没入库"就没处查了（日志会滚掉）；
   * 日志里原样打一条 `[识别] 🚮 …：<原因>`，界面上的"跳过"列表就是丢弃清单。
2. **远端剧集的挂文件**（真机复验才暴露）：`_本地单元们` 原来只会重扫**本地磁盘**，
   网盘路径根本 `is_dir()` 不了 → 一部 16 集的网盘剧只会挂上"第一个视频"。
   P5 补上"读调用方喂进来的 `远端单元` 表还原成一集一个子单元"这条路，
   所以现在 16 集的剧能真的挂上 16 个文件（真机复验断言的就是这个）。

### 5) 学习库（P4）被管线读起来之后，测试要多一道隔离

P5 之前管线不读学习库，所以"人工确认 → 写学习库"那条闭环写在测试里也没人看；
现在识别会读它，于是**同一个测试进程里前一个用例写下的确认会改变后一个用例的结果**
（`test_待确认队列.py::服务队列测试` 的"重搜后仍在队列"就是被上一条写下的
`含糊的名字 → 202` 顶成自动入库的）。修法是给这一类用例一份**自己的**学习库文件
（`mock.patch.object(学习, "默认学习库路径", …)`，与 `tests/test_识别学习.py` 已有做法一致）：
**断言一个字没改**，只是不再跨用例共享状态。这与产品行为无关 ——
真机上"用户点过一次的名字第二次直接命中"正是 P4 要的效果。

同理，单测现在会真的走"扫描 → 识别 → 落库"，于是会写**识别检索缓存**。
`tests/公用.py` 把它也引到临时目录（环境变量 `V2_识别检索缓存`，只在**服务层**认这个覆盖：
`检索.默认落盘缓存路径()` 仍是 P2 的对外契约，`test_识别检索.py` 钉着"必须在数据目录"）。
跑完 `数据/识别检索缓存.json` 一个字节都不会变 —— 用户的目录保持干净。

### 6) 真机复验（用户明确要求的那一步）

`工具/识别端到端真机.py`（**真光鸭 + 真 TMDB + 临时库**）：

```
① 列目录 /来自：分享/仙逆.4K高码.SDR.60fps → 16 个文件
② 16 个「一集一个」→ 合并成 1 个剧目录
③ 第一轮逐集：16/16 自动入库（`146.SDR…` 99.1 分、`Renegade.Immortal…` 122.1 分）
④ 落库：成功 1｜待确认 0｜失败 0；库里 1 条媒体（仙逆/tv/季 1/在线 200 集）
```

### 7) 已知遗留（没做到的、要留意的）

1. **`/来自：分享` 会变成一个查询词**：容器目录 `来自：分享` 不在 `归一化.是通用目录`
   里，于是它作为低权重（57）查询词多搜一次。实测不影响结论（Top-1 依旧是「仙逆」），
   但白花一次请求。要么把这类网盘容器目录加进通用目录表，要么在候选层加"路径前缀"过滤。
2. **"自动入库精确率 100%" 只覆盖已标注的 63 条**：未标注的 28 条（占位样本＋TMDB 上
   对不出唯一条目的 2 条）仍是风险敞口 —— 补真样本比调门槛值。
3. **服务层每部剧最多给 3 条候选取详情**（季集范围＋别名，`候选详情.上限=3`）；
   排在后面的候选拿不到这两样信息，分数会偏低。这是成本取舍（每条候选多 2~3 次请求）。
4. **电影候选也会去问一次别名接口**：真正需要别名的只有"英文/罗马音文件名"，
   但"是不是"要等拿到名字才知道，所以现在对每个头部候选都问一次（真 TMDB 有 7 天磁盘缓存，
   同一部剧几十集只问一遍）。
5. **丢弃不可撤销**：丢弃的条目不进队列，用户只能在任务表的"跳过"里看到它；
   要救回来得走媒体库页的手动匹配（`刮路径(强制标识=…)`）。
6. **`数据/识别检索缓存.json` 会随评测变大**（含评测/真机跑过的查询词）：它是缓存（按天过期），
   不属于用户数据；单测已经引到临时目录，但**跑评测脚本仍会写它**（那是评测的正常产物）。
7. **P4 学习库没有容量上限**：点错/改名换内容后靠 `旧id们` 审计，但没有自动清理策略。
