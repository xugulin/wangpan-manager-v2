* `resizeEvent`（`:302-315`）：把 `堆叠.width()` 广播给实现 `自适应宽度(宽)` 的页面

`应用主题样式(应用, 主题名="") -> str`（`主窗口.py:1398-1417`）是**幂等**入口：
模块级 `_上次样式表: tuple[主题名, QSS] | None`（`:1395`）相同且
`应用.styleSheet() == qss` 时直接返回；否则 `应用全局外观()` + `应用.setStyleSheet(qss)`。
注释说明为什么要幂等（`:1387-1394`：重装同一套会让所有已存在控件重新 polish，

持久化落点：`配置.json` 的 `界面.主题` / `界面.上次网盘` / `界面.终端日志` /
`界面.终端日志级别`（`配置.py:815-833` 的 `界面配置` / `设置界面配置`）。

### 2.4 `控件样式.py`：QProxyStyle 自绘

* `指示器边长 = 16`（`:34`）；`__all__ = ["控件样式","安装控件样式","指示器边长"]`（`:31`）。
* `class 控件样式(QProxyStyle)`（`:49`）：
  * `pixelMetric()`（`:54`）接管 `PM_IndicatorWidth/PM_IndicatorHeight`；
  * `drawPrimitive()`（`:62`）接管 `PE_IndicatorCheckBox` → `_画勾选框`（空心圆角框+勾，
    **不填充**）、`PE_IndicatorRadioButton` → `_画单选框`、`PE_IndicatorArrowDown/Up`
    → `_画箭头`（折角，悬停/按下/展开用强调色）；其余交回 `super()`。
  * 取色一律走 `_颜色(名, 缺省)` → `主题管理器.当前颜色()`（`:29`、`:40-46`）。
* `安装控件样式(应用=None) -> 控件样式 | None`（`:188-204`）：幂等（模块级 `_已安装` `:37`），
  首次 `应用.setStyle(QProxyStyle())`，**基样式取当时的应用样式** —— docstring
  （`:188-193`）明确要求"必须在第一次 `setStyleSheet` 之前"。

⚠️ **唯一调用点** `主窗口._应用主题`（`主窗口.py:1056`）在 `应用主题样式` 之前调用是对的，
但 `运行界面()`（`主窗口.py:1505`）在 `主窗口(...)` 之前就调了一次 `应用主题样式` ——
也就是说实际启动路径上第一次 `setStyleSheet` 发生在 `安装控件样式` **之前**，
`控件样式` 的基样式会是被 `QStyleSheetStyle` 包过的壳，与设计意图不符。

**(h) ⚠️ 换内核时最容易漏的隐式契约**

1. **线程纪律**：`播放会话.界面线程方法`（`播放核心.py:444-446`）把
   `起播/应用新参数/暂停/设置暂停/跳转/停止/截图/设置音量/设置速率/切换字幕/设置缩放/
   设置宽高比/绑定窗口/清掉游离窗口/上报效果` 都套了"非界面线程就排队"的壳
   （`_装界面线程归口` `:448-464`）。界面之所以敢在后台线程里调 `采样并诊断`→`应用新参数`、
   `_自愈画面`→`起播`，全靠这层。新内核必须提供等价的
   `装主线程泵() / 排空主线程队列(最多) / 在主线程(函数, *参数, 等=True, 超时秒=8.0)`
   三件套（界面调用点：`播放页面.py:841,993`、`播放器窗口.py:336,362`）。
2. **窗口句柄语义**：`句柄=0` 在桌面平台 = libvlc 自己开窗（界面必须拦住，
   `播放页面.py:1225-1233`、`播放器窗口.py:412-421`，开关是 `允许VLC自带窗口()`）。
   `起播()` 在有出口但拿不到句柄时**宁可返回 False**（`播放核心.py:641-660`）。
3. **"先停干净再换绑"**：`停止并等待(3.0)` + `等vout消失(3.0)` 是交接能被信任的前提
   （`播放出口.交接` `:183-201`、`播放核心.起播` `:684-690`）。
4. **`安全回退画面` 的阶梯**：`画面回退阶梯` + `设置嵌入输出覆盖(模块)`
   （`播放核心.py:810-822, 907-952`），把 `嵌入输出` 换成 `xcb_xv`/软解。
5. **本地文件路径**：界面会不走 `准备()` 而手工拼 `直链信息/媒体/设置`
   （`播放页面.py:928-940`、`:1511-1527`），因此 `起播()` 必须容忍"未 `准备` 过、
   只有 `直链信息["url"]`"的会话状态。
6. **独立窗口交接包**：`播放器窗口.交接信息()`（`:1740-1759`）把
   `位置秒/网盘标识/远端路径/标题/直链信息/媒体/探测/设置` 打包发给播放页，
   播放页在 `_独立窗口关了()`（`:1573-1607`）里**直接把 `媒体/探测/设置` 塞回会话**，
   所以这四个类型的对象必须可跨实例复用（不能绑定播放器句柄）。
7. **`播放页面._刷新状态` 的 `AI决策状态`** 与 `播放器窗口._刷新状态` 的 `"已结束"/"错误"`
   判续播，都依赖 `状态快照()["状态"]` 的中文字符串（见 §4.2c）。

三层，**界面与凭证层只依赖接口**（`浏览器引擎.py:1-32` 的设计说明）：

```
界面/内置浏览器登录.py   ← 窗口 + 流程 + 收割凭证（552 行，不认识任何浏览器 API）
界面/浏览器引擎.py       ← 接口基类 + 统一 cookie 字典 + 假引擎 + 工厂（367 行）
界面/引擎_QtWebEngine.py ← 唯一实现：QWebEngineView + QWebEngineProfile + 直读 sqlite（416 行）
```

### 5.2 接口（`浏览器引擎.浏览器引擎`，`浏览器引擎.py:105-211`）

`可用() -> (bool, 原因)`（静态）、`打开(url)`、`取视图()`（返回可放进布局的 QWidget）、
`截图()`、`页面地址()`、`页面标题()`、`点(x,y)`、`输入文本(s)`、`按键(k)`、`滚动(增量)`、
`加载中()`、`重新加载()`、`重新挂到(新父)`、`执行JS(脚本)`（同步返回）、
`取cookie(只要名字=(), 域们=())`、`清cookie()`、`关闭()`、`说明()`。

统一 cookie 字典：`COOKIE字段 = ("name","value","domain","path","httpOnly","secure")`（`:39`）；
辅助函数 `规范cookie(项) -> dict`（`:42`，**处理 PySide6 返回 bytes 的坑**）、
`取cookie值(凭证, 名, 域名优先=())`（`:80`）、`拼cookie头(凭证, 只要=())`（`:91`）。
工厂 `建引擎(类型名="", 配置=None, 父=None)`（`:348`）+ `引擎类型 = {"qtwebengine": …,
"假": …}`（`:342`）；建不出来时返回"不可用"的假引擎而不是抛异常（`:363-367`）。
`假引擎(浏览器引擎)`（`:219-334`）用于自检/单测：`预置cookie/预置截图/挂加载回调/
触发加载完成` + `操作记录`。

### 5.3 是否强依赖 QtWebEngine

**不强依赖，但默认实现就是它**：
* `内置浏览器登录.可用()`（`内置浏览器登录.py:75-82`）与
  `QtWebEngine引擎.可用()`（`引擎_QtWebEngine.py:133-140`）都只是
  `try: import PySide6.QtWebEngineCore/QtWebEngineWidgets`，失败返回
  `(False, "内置浏览器不可用（QtWebEngine 缺失）：…")`；
* 所有 QtWebEngine import 都在函数/方法内部（`引擎_QtWebEngine.py:136-137,148-149,161,172,368,377`），
  模块顶层只有 `os.environ.setdefault("QTWEBENGINE_CHROMIUM_FLAGS",
  "--disable-gpu --disable-dev-shm-usage --disable-software-rasterizer")`
  （`:35-37`，注释要求必须在建第一个 QWebEngineView 之前设置）；
* 登录对话框入口先探活再给按钮：`登录对话框.py:285` 用 `内置浏览器登录.可用()` 决定
  `内置浏览器按钮` 是否可用（`:289-299`）；`_内置浏览器登录()`（`:330-368`）里
  `from .内置浏览器登录 import 内置浏览器登录窗口` 失败就弹"不可用"；
* 自检/测试路径可用 `V8_3_只用注入引擎=1` 强制用假引擎，绝不拉起真 QtWebEngine
  （`内置浏览器登录.py:130-142`）。

### 5.4 怎么拿到 cookie（QtWebEngine 实现）

1. **profile 持久化在项目内**：`内置浏览器目录()` = `项目根/数据/内置浏览器`
   （`内置浏览器登录.py:68-72`）；`QtWebEngine引擎` 建 `QWebEngineProfile("v8_3_内置登录",
   父)`，`setPersistentStoragePath(<目录>/storage)`、`setCachePath(<目录>/cache)`、
   `DiskHttpCache`、`ForcePersistentCookies`（`引擎_QtWebEngine.py:150-159`）。
2. **三条路并行**（`取cookie()` `:349-389`）：
   * ① **直读 sqlite**：`读取cookie库(库文件, 需要)`（`:40-103`）读
     `<数据目录>/storage/Cookies`，优先 `file:...?mode=ro&immutable=1`，
     失败才 `copy2` 到临时文件；这就是 `配置["直读cookie库"]=True`（默认，`:128`）。
     注释解释了为什么必须直读：`filterCookies` 按 URL 匹配会漏 `.baidu.com` 域的 BDUSS
     （`:42-46`）。
   * ② `profile.cookieStore().filterCookies([QUrl(u) for u in 过滤网址], 回调)`
     （`:377-379`），`过滤网址` 覆盖百度/夸克/光鸭 8 个域（`:112-117`）；
   * ③ 结果按 `(name, domain)` 去重（`:382-388`）。
3. **两条触发腿**：`profile.cookieStore().cookieAdded` → `_有新cookie` → 窗口
   `_新cookie到了()`（**延迟 400ms** 再查，等 Chromium 落盘，`内置浏览器登录.py:423-430`）
   + 窗口自己的 `QTimer(检查间隔毫秒=1200)` → `_查凭证()`（`:194-197`）。
   ⚠️ 注释强调：持久化 profile 重开时历史 cookie **不会**发 `cookieAdded`，
   必须在 `loadFinished` 里主动查一遍（`引擎_QtWebEngine.py:162-167`、
   `内置浏览器登录.py:344-347`）。
4. **关窗/手动完成前"深取"**：`_最后深取一次(尝试=3)`（`:459-483`），
   `closeEvent` 里用 `尝试=4`（`:499-515`）—— 实测"登录成功立刻关窗"会取到 0 条。
5. **交互全部走注入 JS**（不是 Qt 事件）：`点(x,y)` 派发
   `mousedown/mouseup/click` 到 `document.elementFromPoint`（`:239-254`）；
   `输入文本` 改 `document.activeElement.value` 并派发 `input/change`（`:256-272`）；
   `按键` 派发 `keydown/keyup`，`Enter` 时 `form.requestSubmit()`（`:274-290`）；
   `执行JS` 用 `QEventLoop` + `安全单发(循环, 2500, 循环.quit)` 把异步
   `runJavaScript` 转同步（`:292-313`）。
6. **登录方式**：窗口按 `网盘入口`（`:58-63`）决定入口 URL 与"必需 cookie"：
   `baidu → (https://pan.baidu.com/disk/main, ("BDUSS","STOKEN"))`、
   `quark → (https://pan.quark.cn/, ("__pus","__kps","__uid"))`、
   `guangya → (https://www.guangyapan.com/, ("access_token",))`；
   `登录方式="sms"` + 百度时入口换成 `https://pan.baidu.com/?sms_login=1`（`:226-231`），
   并用 `_切到短信登录()`（`:236-279`，按**文字**找元素，0.5s×12 次重试）与
   `_填手机号()`（`:284-321`，同时写 `encryptMobile` 的 base64）辅助。
7. **凭证回填**：`完成回调(凭证)` → `登录对话框._内置浏览器登录.完成()`（`登录对话框.py:343-352`）
   把 `{"内置浏览器": True, "凭证": [...]}` 序列化成 JSON → `适配器.Cookie登录(载荷)`
   （后台线程）→ 后续由 `_处理结果/_通知成功` 走统一成功路径。

## 7. 给 V2 的整合要点（基于以上事实）

1. **页面装配是可复制的最小闭环**：`QStackedWidget` + `包一层滚动` + "懒加载 + `_切到()`"
   的 8 个页面里，只有 `传输页面`、`网盘页面`、`设置页面`、`AI页面` 与业务强耦合；
   `日志页面`、`敏感词管理页面`、`播放页面`、`空状态页` 可先整体照搬。

   获取主题显示名` + `应用全局外观` + `当前颜色` + 5 个尺寸常量 + `安装控件样式`。
   页面侧一律只写 `setObjectName`，V2 若换 QSS 只需改 `_生成样式表` 一处（1294 行里 763 行）。
3. **换播放内核的边界已经很清晰**：界面**只认** `播放会话`（19 个方法 + 12 个属性）+
   `播放器`（22 个方法/属性）+ `播放出口`（8 个成员）+ `播放设置/媒体信息/探测结果` 三个
   dataclass + 5 个辅助函数（`规则参数/探测媒体/是视频文件/可用/不可用原因`）。

   ⑤ `直链信息/媒体/探测/设置` 可被界面直接赋值。
