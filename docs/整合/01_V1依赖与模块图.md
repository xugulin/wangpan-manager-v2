读法（关键事实）：

* **`界面/` 是唯一的大消费者**：它 import `播放`（25 边）、`核心`（13 边）、`AI`（9 边）；自身内部 63 边。
* **`播放/`、`AI/`、`核心/`、`敏感词/` 之间几乎零耦合**（只有 `核心 → AI` 1 条边、`AI → 核心` 0 条边）。
  `核心 → AI` 的唯一一条是 `核心/传输引擎.py:1220` 的**函数内延迟 import** `from ..AI.队列特征分析 import ...`。
* **`桥/` 只被 `配置.py` 间接使用**（通过 `核心/子进程客户端.py` 以子进程方式拉起），
  桥对主程序只有 1 条反向边：`桥/后端_百度.py:462` 延迟 import `界面.内置浏览器登录`。
* **反向依赖（下层依赖上层）是真实存在的**：
  * `播放/播放出口.py:87` → `界面.窗口就绪`
  * `播放/播放核心.py:759,838,1257` → `播放.显示环境`、`播放.游离窗口`
  * `界面/窗口就绪.py:43,62` → `播放.显示环境`、`播放.游离窗口`
  * `界面/游离窗口守护.py:24` → `播放`
  * `播放/语音识别.py:73` → `自举`
  * `桥/后端_百度.py:462/471` → `界面.内置浏览器登录`

  即 **`播放 ↔ 界面` 是双向耦合**，这是整合时最需要先拆的地方。

## 6. 整合风险点

### 6.1 风险 1（最高）：`核心` 顶层包名冲突 —— 靠 `sys.path` 顺序决定谁生效

* `v8_3/核心/` 与 `适配器/{百度,光鸭,夸克}网盘适配器/核心/` 是**四个同名顶层包 `核心`**。
* `v8_3/桥/后端_*.py` 在函数体内 `from 核心.认证.认证服务 import 认证服务` 等 14 类目标，
  这些名字**在 `v8_3/核心/` 下全部不存在**，只有适配器项目里有。
* 桥进程能跑通，**完全依赖** `桥/工作进程.py:56-57` 的 `sys.path.insert(0, self.project_root)`
  跑在 `_装载后端()` 之前。同时 `核心/子进程客户端.py:96-97` 又把 `PYTHONPATH=项目根` 传进去，
  也就是说 `核心` 这个名字在同一个解释器里**同时存在两个合法候选**。
* 后果：任何 `sys.path` 顺序变化（打包成 zip、改用 `importlib` 元路径、把 `v8_3` 装成 site-package、
  或未来把 `v8_3/核心` 改名）都会让桥静默导入**错误的 `核心`**，表现为
  `ModuleNotFoundError: No module named '核心'` 或更糟的「导入成功但类是错的」。
* 建议：整合时把 `v8_3/桥/` 与适配器 `核心` 的引用改成**显式包前缀**，
  或干脆把适配器 `核心` 改名为 `适配器核心`/`<网盘>_核心`。

### 6.2 风险 2：`桥/` 的同目录裸导入依赖 `cwd` + `sys.path[0]`

* `from 后端_基类 import ...`（4 个文件）只在「脚本目录被放进 `sys.path[0]`」时成立。
* 同时 `核心/子进程客户端.py:37-48 _绝对本地路径()` 的注释记录了实际踩过的坑：
  桥进程 `cwd=v8_3/桥`，相对路径会被解析到 `v8_3/桥/数据/...`，
  所以**所有交给桥的本地路径都必须先绝对化**（现已做，但属于隐式契约）。
* 任何改成 `python -m v8_3.桥.工作进程`、或改成 `importlib`/冻结打包的整合动作都会打断它。

### 6.5 风险 5：`os._exit()` 与 `atexit` 主动结束进程

* `界面/主窗口.py:1436-1478 _收尾退出()`：事件循环结束后等遗留 QThread 最多 `宽限秒`，
  然后 **`_os._exit(int(退出码))`**（仅在**非** unittest/pytest 进程）。
* `界面/主窗口.py:1441-1456 _注册遗留线程收尾()`：注册 `atexit.register(_收尾退出, 0, 0.2)`。
* 注释说明原因：留存运行中的 QThread 会被 GC 回收 → Qt `Fatal Python error: Aborted`（实测核心转储）。
* **整合风险**：`os._exit()` 会**跳过所有 atexit/清理**，包括日志刷盘、
  `敏感词数据库` 的写缓冲、`AI播放学习.db` 的 WAL 检查点、子进程的优雅关闭。
  若整合后有别的守护线程需要 flush，会被直接砍掉。
