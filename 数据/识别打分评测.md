## 八、已知限制与下一步

1. **只给头部 3 条候选取详情**：排名靠后的候选拿不到季集范围与别名，所以它们的分数可能偏低（这是成本取舍：每条候选多两次请求）。
2. **TMDB 名字走公开接口**：`TMDB客户端.取别名们`（P5 补的）把 `alternative_titles` + `translations` 包成一处，`identify.详情` 与 `服务.py` 共用它；假客户端没有它时退回带缓存的私有 `_取一份`（拿不到就当没有别名）。
3. **未标注的 28 条无法判定**（占位样本「某剧」/「某番」+ TMDB 上对不出唯一条目的 2 条），自动入库精确率的**风险敞口**就是它们 —— 把它们补成真样本比调门槛更值。
4. **待确认 14 条**全是「分不够高 / 领先不够多 / 同名列不出唯一」（不是「选错了」）：这正是 P4 的入口 —— 用户点一下就写成「目录→作品 / 别名→作品」的学习样本，第二次识别直接命中（那时 ⑤ 的学习库信号 +45 分会把它们送进自动档）。
5. **「精确一致唯一」会免掉绝对分与间距**（`决策._精确一致`）：片名逐字一致 + 年份完全一致 + 类型一致，并且候选里**只有一条**满足 → 直接自动入库（老实现真机验证过的规则）。所以本表的门槛敏感性里，收紧门槛那一行仍会有 22 条自动 —— 它们不是被门槛放进去的，是被这条规则认出来的。
